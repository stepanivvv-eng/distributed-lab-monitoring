# Распределённая система мониторинга и управления лабораторным оборудованием

Система телеметрии и дистанционного управления для действующего лабораторного
оборудования: автоклава, холодильника с термостатом, фитотрона и защитного
бокса с УФ-лампой. Проект выполнен в рамках научной работы и ориентирован на
частные и школьные лаборатории: ретрофит существующих приборов без вмешательства
в их штатную автоматику.

## Архитектура

Трёхуровневая схема «узлы — шлюз — сервер»:

```
[Узлы ESP32] --ESP-NOW--> [Шлюз ESP32-S3] --Ethernet--> [Сервер]
                                                                ├─ Home Assistant
                                                                ├─ Mosquitto (MQTT)
                                                                ├─ InfluxDB
                                                                └─ Grafana
```

- **Узлы** (ESP32 DevKit V1) опрашивают датчики и управляют нагрузкой через
  твердотельные реле. Сами по себе выполняют локальную аварийную защиту
  (термозащита, автоотключение УФ-лампы) и не зависят от сети.
- **Шлюз** (ESP32-S3) принимает пакеты по ESP-NOW и публикует телеметрию
  на сервер (Home Assistant / MQTT), а также передаёт команды управления
  обратно узлам. ESP-NOW работает без подключения к Wi-Fi-сети — узлы
  не зависят от роутера.
- **Сервер** — Docker-стек: Home Assistant (логика и интерфейс),
  Mosquitto (MQTT-брокер), InfluxDB (хранение временных рядов),
  Grafana (визуализация).


## Программная часть

Прошивки узлов и шлюза — декларативные конфигурации
[ESPHome](https://esphome.io) (фреймворк на базе ESP-IDF), без собственного
кода на Arduino: вся логика опроса датчиков, разбора пакетов и публикации
состояний описана в YAML с лямбда-выражениями. Серверная часть развёрнута
в Docker-контейнерах.

> Ниже приведены **иллюстративные фрагменты**, показывающие принципы
> реализации. Рабочие конфигурации с полной логикой находятся в файлах
> выше — они снабжены комментариями.

### Пример: датчик узла

Любой датчик в ESPHome описывается декларативно — пины, адрес на шине,
период опроса. Значение автоматически упаковывается в пакет протокола
и уходит на шлюз по ESP-NOW:

```yaml
sensor:
  - platform: dht
    pin: GPIO4
    model: DHT22
    temperature:
      name: "temperature"
      accuracy_decimals: 1
    humidity:
      name: "humidity"
    update_interval: 5s

  - platform: bh1750
    address: 0x23
    update_interval: 5s
```

### Протокол ESP-NOW

Обмен — короткие пакеты (до 11 байт) по MAC-адресу узла, без установки
соединения. Первый байт — тип пакета. Значение 0xFF / 0xFFFF в поле данных
означает «датчик недоступен» — так система различает отказ и ноль.

| Тип | Назначение | Формат |
|---|---|---|
| 1 | Освещённость | `{1, hi, lo}` (0xFFFF = нет данных) |
| 2 | Влажность почвы (10 каналов) | `{2, s1..s10}` (0xFF = нет данных) |
| 3 | Температура | `{3, hi, lo}` (0x7FFF = нет данных, 0.1 °C) |
| 4 | Влажность воздуха | `{4, h}` |
| 5 | CO₂ | `{5, hi, lo}` |
| 6 | Подтверждение состояния реле | `{6, lamp, fan, fan_mode}` |

Команды сервера — те же пакеты в обратную сторону:

| Тип | Назначение | Формат |
|---|---|---|
| 10 | Вкл/выкл нагрузки | `{10, 0/1}` |
| 11 | Режим / уставка | `{11, mode}` или `{11, hi, lo}` |

Команды имеют подтверждение: узел отвечает пакетом с фактическим состоянием,
поэтому система обнаруживает потерю команд, а не только потерю телеметрии.

### Пример: приём и разбор пакета на шлюзе

Шлюз в обработчике `espnow.on_receive` по MAC-адресу отправителя определяет
узел, а по первому байту — тип пакета, и публикует значение во внутренний
сенсор (уже дальше — в Home Assistant / MQTT):

```yaml
espnow:
  on_receive:
    - then:
        - lambda: |-
            if (data[0] == 3 && size == 3) {
              // Температура: {3, hi, lo}, 0.1 °C, 0x7FFF = нет данных
              uint16_t v = (data[1] << 8) | data[2];
              id(node_temp).publish_state(v == 0x7FFF ? NAN : (int16_t) v / 10.0f);
            }
```

### Пример: команда управления из Home Assistant

Переключатель на шлюзе отправляет командный пакет адресату по ESP-NOW.
Состояние в интерфейсе обновляется по пакету-подтверждению от узла:

```yaml
switch:
  - platform: template
    name: "lamp"
    turn_on_action:
      - espnow.send:
          address: !secret node_mac
          data: [10, 1]
    turn_off_action:
      - espnow.send:
          address: !secret node_mac
          data: [10, 0]
```

### Пример: публикация в MQTT

При наличии компонента `mqtt:` состояния всех сенсоров публикуются
автоматически, дополнительный код не требуется:

```yaml
mqtt:
  broker: 192.168.0.103
  username: !secret mqtt_user
  password: !secret mqtt_pass
  topic_prefix: lab/gateway
```
